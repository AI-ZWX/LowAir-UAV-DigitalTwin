# 低空数字孪生——用 AI 解决真实问题

用 AI 辅助开发低空无人机数字孪生系统，实际碰到的、卡住的、最终解决的问题记录。

> 没有设备，没有飞控数据，没有倾斜摄影。但模拟里暴露的问题——光照失控、颜色撞色、材质消失——都是真实场景里会发生的。提前踩一次，以后至少知道从哪下手。

**每个问题记录四件事**：怎么试的 → 败在哪 → 根因是什么 → 留下了什么教训。

## 问题记录

- **[用 AI 辅助开发数字孪生：我的实际工作流](./articles/AI辅助数字孪生开发-实际工作流.md)** —— 人和 AI 怎么分工、实际碰到的排查例子、什么时候 AI 帮不上忙。

- **[场景里 11 种颜色互相撞色](./articles/2026-09-02-颜色撞色三轮排查.md)** —— 改了一个颜色，三个地方炸了。正解是符号+颜色双通道。

- **场景过曝发白** —— GameMode 强制把所有后期体设为 Unbound，多光源叠加不可控。根因是光照控制权分散，不是曝光参数。

- **围栏在 Lit 渲染模式下消失** —— Python 材质 API 改节点后 Emissive 链断开，材质输出为零。验证：Python MaterialEditingLibrary 不可靠，需要三重验证才能确认落盘。

- **多机同时触发告警刷屏** —— 改模拟器飞行高度后，所有无人机突破限高规则，右栏告警被刷屏。根因：改参数前没核对全部规则阈值。

- **架构决策记录** —— 渲染方案、通信协议、数据存储，5 篇 ADR。每个决策都记录了当时的约束和取舍。

## 工具和协作

AI 编程助手是日常协作者——拆解问题、对比方案、生成排查脚本。人做决策（根因在哪、设计对不对），AI 做加速（改了这个参数会影响哪、这个 API 能不能用、逻辑通不通）。

一个人开发没有团队讨论，AI 就是随时在线的协作者。但它替不了判断——技术选型、什么时候推翻重来，只能自己决定。
