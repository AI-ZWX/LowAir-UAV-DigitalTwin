# 低空数字孪生——模拟现实，解决问题

> 不是在搭 Demo。是在模拟真实场景中会遇到的问题，用 AI 辅助逐个解决，记录全过程。

## 这里有什么

我是一个转行到低空经济方向的开发者。这个仓库记录的是：在没有真实设备、真实飞控、倾斜摄影数据的情况下，模拟低空无人机监管场景会遇到的问题，借助 AI 协作逐个解决。

每个问题都走完：**用什么方法试了→为什么失败→根因是什么→怎么解决的→留下了什么教训**。

## 已经解决的问题

- **[场景里 11 种颜色互相撞色](./articles/2026-09-02-颜色撞色三轮排查.md)** —— 改一个颜色，另外三个地方炸了。三轮排查后发现颜色通道已经饱和，正解是符号+颜色双通道。HDR 色值 ≠ 渲染值，纸面调色没用，必须 PIE 截图闭环验证。

- **场景过曝发白** —— GameMode 强制把所有后期体设为 Unbound，多个光照源叠加不可控。根因不是曝光参数，是光照控制权分散。在不确认硬件/资产条件时不承诺非示范效果。

- **围栏在 Lit 渲染模式下消失** —— Python 材质 API 改了节点但 Emissive 链被拆断，材质输出为零。验证结论：Python MaterialEditingLibrary 在本环境不可靠，需要磁盘时间戳+节点输入三重验证才能确认落盘。

- **多机同时触发告警刷屏** —— 改了模拟器飞高度后，所有无人机突破限高规则，右栏告警被刷屏，顶栏威胁计数失效。根因：改遥测参数前没有核对全部规则阈值。

- **架构决策：渲染方案、通信协议、数据存储** —— 5 篇 ADR，每个决策都附了当时面临的约束条件和取舍。没有"最佳实践"，只有"在具体条件下最合理的选择"。

> 待整理的问题还有：无人机模型从几何块到写实机型的迭代、Cesium 瓦片在 UE5 中的性能实测、WGS84 到 UE 世界坐标的完整转换链。

## 工具和协作方式

这些问题不是一个人闷头解决的。

主要的协作工具是 **Claude Code**（AI 编程助手）——帮助拆解问题、对比方案、审查代码、生成排查脚本。人是决策者，AI 是多线程加速器。分工很清楚：**人在想"根因在哪"、"设计对不对"，AI 在跑"这个参数改了会影响哪儿"、"这个 API 能不能用"、"这个逻辑通不通"**。

> 待业期间没有团队可以讨论，AI 就是那个随时在线的协作者。但它替不了人的判断——技术选型、架构取舍、什么时候该停、什么时候该推翻重来，这些只能自己决定。

## 为什么记录

模拟当然不等于真实。但在模拟中暴露的问题——光照管线混乱、颜色通道饱和、坐标转换精度、实时与回放数据隔离——不管以后有没有真实设备，只要做数字孪生就会遇到。提前碰到一次，以后真遇到知道从哪下手。

更重要的是，记录本身就是消化。写的过程会逼自己把"模糊觉得懂了"变成"能清晰讲给别人听"。
