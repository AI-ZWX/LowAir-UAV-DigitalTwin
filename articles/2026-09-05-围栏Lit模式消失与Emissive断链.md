# 围栏在 Lit 渲染模式下消失：Emissive 链接断开了

## 先说结论

**一个返回 `False` 的 API，能让材质悄悄变成全透明，日志里不会有任何记录。** 在 UE 里用 Python 脚本改材质节点时需要注意这一点。脚本是不是自己写的，不影响这个问题的存在——这篇里的脚本就是 AI 写的，问题一样出现。

## 当时发生了什么

2026-09-05，给电子围栏的材质做视觉调整。目标很小：让 M_FenceYellow 和 M_FenceRed 在场景里更醒目一点，加个边缘发光。

这类实现工作在这个项目里交给 AI：我提目标，AI 写 Python 脚本。脚本做了三件事：改成 UNLIT、加 Fresnel 节点、加 EdgeBoost 节点。跑完，日志里 `ShadingModel=0 (UNLIT)` 明明白白，材质文件也落盘了。看起来一切正常。

开 PIE 一看：

**Unlit 视口下，围栏 A 是紫的，围栏 B 是青绿的，地标光柱正常立着。切换到 Lit 游戏渲染——围栏不见了。**

不是变黑，是全透明，像不存在一样。

## 排查过程

**第一步：确认 UNLIT 是否生效。** 日志里 `ShadingModel=0` 白纸黑字，这个方向直接排除。

**第二步：检查颜色是否接上。** 用 `get_material_property_input_node` 查 Emissive 的输入端——结果是 NONE，悬空的。输出端没接任何东西，UNLIT 材质的发光值就是 0，等于全透明。Lit 渲染下既没有正常光照链路，自发光又是零，就什么都不剩。"消失"这个现象由此解释通了。

**第三步：确认链接是什么时候断的。** 回头读 AI 写的脚本。STEP5 加 Fresnel，需要把原来的 Emissive 链拆开、插进新节点、再重新连回去。拆开和重连用的是一个 API：`connect_material_expressions`。

把这一步单独拎出来测：这个 API 在我的环境里**每一次都返回 False**。不是偶尔失败，是每一次。问题在于它不抛异常、不警告、不写日志，只返回一个 False——发现的时候，材质已经"改完"了。

旁边还有一个佐证：另一个材质 M_SceneDarken，四条连接全部返回 False。不是哪一步写错了，是这个环境里的这类 API 不可靠。

事故链是这样的：

```
AI 脚本拆开了原 Emissive 链
→ 重连 API 返回 False（没人知道）
→ 链断着，输出悬空 = 0
→ UNLIT 发光值 = 0
→ 围栏全透明 → "消失"
```

## 根因

UNLIT 化本身没错。错在 Fresnel 那一步把 Emissive 链拆了之后，没接回去——**而 API 用返回 False 的方式报告了"没接回去"，我和 AI 都默认了"没报错就是成功了"。**

责任划分：脚本是 AI 写的，验收是我的。判断"这个材质真的改对了吗"是我的工作——AI 不会替我做这个判断。

## 怎么修的

回滚 M_FenceYellow / M_FenceRed 的 Fresnel 修改，把原始 Emissive 直连链恢复出来，UNLIT 保留。回滚只能手动在编辑器里核对做——`.uasset` 不进 git，无法靠版本控制回滚。第二天（09-06）确认恢复。
