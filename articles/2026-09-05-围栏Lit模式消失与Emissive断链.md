# 围栏在 Lit 渲染模式下消失：断掉的链条，API 一个字都没提

## 先说结论，给赶时间的人

**一个返回 `False` 的 API，能让你的材质悄悄变成全透明，而且日志里什么都不会有。**

如果你在 UE 里用 Python 脚本改材质节点，这篇能帮你少熬一个通宵。脚本是不是你自己写的，一点都不影响这个坑的成色——这篇里的脚本就是 AI 写的，坑一样照踩。

## 当时发生了什么

2026-09-05，给电子围栏的材质做视觉调整。目标很小：让 M_FenceYellow 和 M_FenceRed 在场景里更醒目一点，加个边缘发光。

这类实现工作在这个项目里交给 AI：我提目标，AI 写 Python 脚本。脚本做了三件事：改成 UNLIT、加 Fresnel 节点、加 EdgeBoost 节点。跑完，日志里 `ShadingModel=0 (UNLIT)` 明明白白，材质文件也落盘了。一切看起来都成功了。

开 PIE 一看，人傻了：

**Unlit 视口下，围栏 A 是紫的，围栏 B 是青绿的，地标光柱好好立着。切换到 Lit 游戏渲染——围栏没了。**

不是变黑，是消失。透明到像从来没存在过。

## 排查过程

**第一反应：UNLIT 没生效。** 查日志，`ShadingModel=0` 白纸黑字。这个方向死得最快。

**第二反应：颜色没接上。** 用 `get_material_property_input_node` 去查 Emissive 的输入端——查到的结果是 NONE。悬空的。输出端什么都没接，UNLIT 材质的发光值就是 0，等于全透明。Lit 渲染下既没有正常光照链路，自发光又是零，就什么都不剩。到这里，"消失"这个现象解释通了。

**第三问：链是什么时候断的？** 回头读 AI 写的脚本。STEP5 那步加 Fresnel，需要把原来的 Emissive 链拆开、插进新节点、再重新连回去。拆开和重连用的是一个 API：`connect_material_expressions`。

把这一步单独拎出来测：这个 API 在我的环境里**每一次都返回 False**。不是偶尔失败，是每一次。最坑的是——它不抛异常、不警告、不写日志，安安静静返回一个 False，等你发现的时候，材质已经"改完"了。

旁边还有一个佐证：另一个材质 M_SceneDarken，四条连接全部返回 False。不是哪一步写错了，是这个环境里的这类 API 就是不可靠。

事故链拼起来是这样的：

```
AI 脚本拆开了原 Emissive 链
→ 重连 API 返回 False（没人知道）
→ 链断着，输出悬空 = 0
→ UNLIT 发光值 = 0
→ 围栏全透明 → "消失"
```

## 根因

UNLIT 化本身没错。错在 Fresnel 那一步把 Emissive 链拆了之后，没接回去——**而 API 用返回 False 的方式报告了"没接回去"，我和 AI 都信了"没报错就是成功了"。**

责任怎么分：脚本是 AI 写的，但验收是我的。AI 不会替我做"这个材质真的改对了吗"这个判断——它给了我能看懂的所有信号，读懂它们是我的活。

## 怎么修的

回滚 M_FenceYellow / M_FenceRed 的 Fresnel 修改，把原始 Emissive 直连链恢复出来，UNLIT 保留。回滚只能手动在编辑器里核对做——`.uasset` 不进 git，没有 `git checkout` 可以救命。第二天（09-06）确认恢复。

## 给看的人一句警醒

**返回布尔的 API，不报错不等于成功。** 尤其是批量改资产的脚本——写脚本的是人还是 AI，这个坑的分量一模一样。一个 False 混在一堆成功日志里没人会看见，等你看见的时候，付出的可能是一个"场景里东西莫名其妙消失"的通宵。改材质这种动一刀全场景都受影响的操作，宁可慢，不要信。
