# 开发机中了银狐木马：从"微信自己动"到彻底根除两波感染的全记录

> 2026-09-12。上午吃东西回来，发现电脑微信正在自己加群、发消息。
> 这篇文章记录整个过程：怎么发现的、怎么取证的、怎么被木马"反杀"的、最后怎么连根拔掉的。
> 按[本仓库的记录格式](../README.md)：怎么发现的 → 走了哪些弯路 → 根因是什么 → 留下了什么。

## 先说结论（给没耐心看长文的）

1. **中了两波独立的木马**：一波潜伏 7 个月没被发现，一波是当下正在活动的银狐（Silver Fox）远控
2. **杀毒软件瘫痪 4 天的真正原因不是被停用，而是被一条伪装成微软官方模板的 WDAC 应用控制策略拉黑了**——这是整个事件里最隐蔽的一手
3. 入口是搜索引擎能搜到的"假 Gemini 官网"下载的安装包（签名被篡改）
4. 清理完成后做了系统加固 + 凭据全量轮换 + 自动化监控，并把这套方法做成了可复用的脚本
5. **最大教训：防篡改保护（Tamper Protection）没开，等于给木马留了后门**

---

## 一、发现：微信在自己动

上午吃东西回来抬头，屏幕上微信正在加群、发消息——鼠标没动，人不在电脑前。

第一反应不是"中毒了"，而是"是不是误触"。但强制退出微信、几分钟后再登录，又开始自动加群。这就对不上了：**微信本体是从官网装的，进程签名正常，但有人在远端操控它**。

这里有个关键判断：微信没中毒，中毒的是操作系统——木马在桌面层操控真实客户端。这也意味着查微信没用，得查整个系统。

## 二、取证：三分钟锁定银狐

用系统自带工具做了一轮快速取证（全程不需要第三方杀软，因为怀疑杀软已经不可信）：

**进程与网络**：发现三个随机名进程（`8HIqCN.exe`、`Q2VhVL.exe`、`NkmkYHge.exe`）正保持着到境外 IP 的长连接。

**注册表自启动**：HKLM\Run 里躺着三个伪装项：

```
Tencent SecurityHealth   →  C:\Users\Public\eiekN5\8HIqCN.exe
Alibaba SecurityHealtha  →  C:\Program Files (x86)\60lnjU1\SM2p3rjHo.exe
Alibaba SecurityHealthb  →  C:\Program Files (x86)\uCTjvP\Q2VhVL.exe
```

"腾讯/阿里安全中心"的假名 + 随机目录随机文件名——银狐木马的标志性马甲。

**文件时间戳**：所有恶意文件创建于 9/8 上午 11:20-11:24，4 分钟内完成部署——自动化投放，不是人为安装。

**Windows 日志**：Defender 事件 5007 显示 9/8 11:21-11:24，有程序把**整个 C 盘**加入了 Defender 排除项，然后停用了 Defender。同分钟还创建了一个伪装成 `.jpg` 的内核驱动服务 `TCLService`（`C:\Windows\Temp\ranchserv.jpg`）——后来查证这是银狐新变种的 BYOVD 组件，专门按 PID 强杀安全软件进程。

对照 CNCERT 的[银狐钓鱼网站风险提示](https://www.cert.org.cn/publish/main/10/2026/20260522113326926111046/20260522113326926111046_.html)，家族判定确认。

## 三、找入口：浏览器下载记录说话

杀软日志给出了精确的感染时间窗（9/8 11:20），那么 11:19 之前用户干了什么？

Chrome 的 `History` SQLite 库里 `downloads` 表给出了答案：

```
09-08 11:19 | installer_r2.0.09.zip | https://cm-gemini.com.cn/
```

**从"cm-gemini.com.cn"（仿冒 Google Gemini 的假官网）下载的安装包**。解压出的 exe 签名状态是 HashMismatch（签过名但内容被篡改）。11:19:42 运行，11:20:26 木马落盘。时间线分秒咬合。

教训写在这里：搜"某 AI 工具官网"，排在前面的可能是广告位假站。正规 Gemini 只有 gemini.google.com，任何 `.com.cn` 的"Gemini 官网"都是钓鱼。

## 四、清理：三回合的攻防

### 第一回合：常规清除

提权脚本一次做完：杀进程 → 删 4 个恶意计划任务（含两个仿"MicrosoftEdgeUpdate"的）→ 删 3 个假自启动键 → 删 TCLService 驱动服务 → 隔离全部样本。

结果：**4 个目录删不掉**。木马给文件设置了拒绝管理员访问的 ACL + 只读属性——银狐的抗清理手法。

### 第二回合：ACL 对抗

`takeown` 接管所有权 → `icacls /reset` 重置 ACL → 删除。四个目录全部拿下。

### 第三回合：抓住漏网活体

全盘扫描 8/29 以来新增的可执行文件（4114 项逐一分类），发现 `C:\ProgramData\Eou4ZRjl.exe`——与木马同批落地、不在任何持久化清单里、**取证时正在运行**的休眠组件。杀掉、隔离、删除，观察无复活。

**这一步的教训**：清理永远要"全盘新文件扫描"收尾，不能只清持久化清单上列出来的。木马会有清单外的休眠组件。

## 五、意外发现：潜伏 7 个月的第二波感染

Defender 复活后跑了脱机扫描，直接报了**另一个严重级木马**：`Trojan:Win32/Vigorf.A`。

- 伪装：`AppData\Roaming\Portmaster\Sync\CloudAgent\`——但本机从没装过 Portmaster
- 本体：自带全套 Python 运行时（`tpm2emu.exe` 是改名的 python.exe，带官方签名），真载荷是随附的 asar 文件
- 持久化：仿 OneDrive 命名风格的计划任务
- **目录创建时间：2026-02-23。潜伏了 7 个月**，每天就在任务管理器里挂着，没人看它一眼

这意味着凭据泄露风险要从 2 月起算——所有 API Key、密码全部按已泄露处理，全量轮换。

**教训**：杀软的"实时保护正常"不等于"系统干净"。定期脱机扫描（重启进 WinPE 环境、绕开系统内一切驻留）是唯一能绕过运行期对抗的手段。

## 六、最隐蔽的一手：WDAC 策略封杀

清理完所有已知恶意项后，Defender 还是起不来，报错"应用程序控制策略已阻止此文件"。

CodeIntegrity 日志（事件 3077）显示策略 ID `{a244370e-...}`——但它不在系统正常策略清单里。最终定位：

```
C:\Windows\System32\CodeIntegrity\SiPolicy.p7b
创建时间：2026-09-08 11:21:12（与木马落盘同分钟）
```

提取内容分析：策略伪装名是微软官方模板名 `AllowMicrosoft_2023-05-04`，但规则实际是**一份杀软封杀名单**——显式拉黑 360 全家、Avast、AVG、Avira，同时要求"企业签名级别"把 Defender 自己的 exe 全部拦死。

这就是 Defender 四天起不来的根本原因。删除策略文件、重启，Defender 立刻复活。

**为什么会有这么大的空子**：本机的**防篡改保护（Tamper Protection）没开**。这个开关开着的话，任何程序（包括管理员权限的程序）都无法修改 Defender 设置、更没法植入系统级策略。一次没开，四天裸奔。

## 七、善后：账号、加固、自动化

### 账号（按风险顺序）

1. 微信/QQ：登录设备管理踢掉电脑 + 改密 + 检查支付账单
2. 所有 API Key（云端控制台作废重发）——尤其硬盘上明文存着的那批
3. Google 等核心账号改密 + 开两步验证 + 踢全部会话
4. 浏览器保存的密码逐一轮换

### 系统加固（企业级基线）

防火墙三档全开、UAC 最高、自动播放禁用、共享盘全关（C$/E$/F$/ADMIN$/IPC$…）、LLMNR 禁用（防哈希窃取）、文件打印共享全关、遥测降级、**防篡改保护开启**。

### 自动化监控（让防护不依赖人记性）

- **下载安全监控**：FileSystemWatcher 常驻监控下载目录，可执行文件落地 1 秒内算哈希送 VirusTotal（70+ 引擎），恶意自动隔离 + 弹窗。实测 EICAR 测试文件，Defender 毫秒级先拦了一道，VT 作第二道
- **每周自动备份**：Windows 任务计划每周日推送三个 git 仓库到远端私有库——代码有远端副本，中招也不怕丢
- **观察期复查**：连续两周每周日自动复查恶意项是否复活

## 八、对数字孪生项目的直接影响

这台开发机上跑着低空数字孪生系统（UE5 + WebSocket 网关 + 模拟器）。事件暴露的问题直接落地成了[项目安全基线（SECURITY.md）](https://github.com/AI-ZWX/L4TwinSlice)：

- 网关/模拟器端口收口 `127.0.0.1`（局域网不可达）
- npm 依赖审计（官方源，0 漏洞确认）
- 计划任务以低权限运行
- **部署前十条铁律**写进 SECURITY.md：鉴权、TLS、最小暴露、专用低权账户……任何一条不做，不得对局域网/公网开放服务

开发机上能被木马读走的东西，部署后的服务器同样能被读走。**本机的安全短板就是未来生产环境的短板**——这句话是整个事件最值钱的认知。
