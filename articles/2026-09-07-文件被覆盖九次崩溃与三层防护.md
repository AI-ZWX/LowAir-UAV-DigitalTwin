# 一个文件被覆盖，一天崩溃九次：三层防护是怎么被逼出来的

> 现象一句话：2026-09-07 从凌晨到下午连续 9 次引擎崩溃，最后发现是一个源文件的内容被整个换成了另一个文件的——而这不是第一次，只是最疼的一次。

## 现象

9 月 7 日凌晨 0:09 第一次崩溃，到 14:35 已经 9 次。崩溃形态一致：`EXCEPTION_ACCESS_VIOLATION writing address 0x01c5`，空指针写入，`Saved\Crashes` 里躺了一排记录。

项目当时处于 P0 编码收尾阶段，改动密集。每次崩溃后重启、再改、再崩，循环了一整天。

## 排查路径

从崩溃日志往前倒。所有崩溃都指向同一片区域，最后定位到一个具体文件：`AlertHUDManager.cpp`。

疑点在于它的**大小**：16822 字节——和 AlertTimelineWidget.cpp 一模一样大。打开看，内容也一模一样：**这个文件的内容被整个覆盖成了 AlertTimelineWidget.cpp**。

时间线拼出来了：

- 19:58（前一晚）最后一次"修改" AlertHUDManager.cpp——那次写入就是把别的文件内容写了进去；
- 编辑器一直开着。Live Coding 热重载尝试编译这个文件，编译单元内容完全错乱，编译失败；
- 引擎加载了损坏的二进制和符号 → 空指针写入 → 崩溃。编辑器开着的状态下反复触发，就是一天 9 次的原因。

修复本身倒不复杂：用 `git show HEAD:./Source/.../AlertHUDManager.cpp` 把原始内容从版本库里捞出来，重新打上本来要做的修改（HUD 卡片的安全矩形夹持：顶栏 40px、左栏 240px、右栏 320px 边界内），清理掉根目录积累的 40 多个诊断脚本，崩溃停止。

## 但这只是第三次，不是第一次

把前后的事故摆在一起，会发现一个共同模式——**"运行的代码，不是你以为的代码"**，三次事故三个形态：

**8/23：改了，没编进去。** 无人机颜色修复合入后，重启运行还是旧颜色。代码逻辑、材质资产、参数写入链路全部排查正确，现象就是不变。突破口在二进制层：DLL 的编译时间 11:59:38，**早于**所有源码修改时间（13:59/13:19）。新代码从来没被编译进二进制。还有一个干扰项：用 MCP Python 直接改运行时材质参数，颜色立即生效，几秒后又被旧逻辑覆盖回去——这个现象差点把人带向"资产有问题"，实际上恰好证明了运行的是旧代码。

**9/7（本次）：文件内容被覆盖。** 写的和跑的不是同一个东西，编译链直接崩掉。

**9/8：编了，没生效。** 围栏虚线和地标光柱悬浮在空中，离地 64.3 米。第一反应是高程数据错了，但用运行时工具实测坐标转换函数——输出完全正确（期望 15.5m 的位置函数给了 15.49m）。再读 Actor 实际位置：79.8m。查源码和 DLL 的时间戳：源码改到 17:11，DLL 停在 13:13。**又是旧二进制**。停 PIE、Live Coding 编译、重启 PIE，围栏落回 15.5m，20 分钟解决。

## 根因

三次事故的共同根因不是"某个操作失误"，而是：**整个工作流里没有任何机制保证"运行的代码 = 你以为正在运行的代码"。**

文件可能被覆盖（9/7）、改了可能没编译（8/23）、编译了 PIE 可能没重载（9/8）——每个环节都靠人记、靠人查。一个人加多个 AI 协作者高频改动的场景下，人的记忆是最不可靠的一环。

还有一个共性值得单独说：8/23 和 9/8 两次，**现象都完美伪装成数据问题**（旧颜色、悬浮 64 米），而真实原因是工具链。如果按现象直接修数据，会永远修不好。

## 修复

9/21 起三层防护全部在岗，每一层对应一个事故形态：

1. **写盘前校验**：`Protect-L4SourceWrite.ps1`——AI 改 `Source/` 或 `Content/` 任何文件前必须跑，校验文件内容与其身份一致，退出码非 0 禁止写盘。对付 9/7 型事故。
2. **pre-commit 钩子**：提交前再拦一道。对付绕过脚本的写盘。
3. **WriteGuard**：编辑器侧的写保护。对付编辑器内的误操作。

外加一条工作流纪律写进了项目指令：改完代码不编译不验，等于没改。

## 下回怎么做

- [ ] **写盘前跑校验脚本，退出码非 0 立即停手**，不抱"这次应该没事"的侥幸
- [ ] **"行为不对 / 位置不对"类问题，第一动作是核对 `Binaries/Win64/*.dll` 时间戳 vs 源码修改时间**，确认运行的是新代码，再开始怀疑数据
- [ ] **Live Coding 编译成功后必须重启 PIE**，旧会话不会自动应用补丁
- [ ] **用实测对位排查，不用猜**：调一次坐标转换函数看输出，对比 Actor 实际值，30 秒就能分清是"算错了"还是"没生效"
- [ ] **AI 协作时，"文件名和内容一致"交给工具校验，不靠眼睛看**
- [ ] **崩溃排查先看崩溃记录的时间和形态，找规律再动手**，不要被第一个嫌疑对象带走
