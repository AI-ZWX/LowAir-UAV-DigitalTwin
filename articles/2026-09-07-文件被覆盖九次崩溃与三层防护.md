# 一个文件被覆盖，一天崩溃九次：最疼的那次事故，逼出了三层防护

## 先说结论，给赶时间的人

**"你运行的代码"和"你以为你在运行的代码"，可能是两个东西。** 一年内我撞了三次，三个形态。如果团队里还有 AI 在帮你写代码，这条值得抄走。

## 那天发生了什么

2026-09-07。凌晨 0:09 第一次崩溃，到下午 14:35，第 9 次。

崩溃的形态一模一样：`EXCEPTION_ACCESS_VIOLATION writing address 0x01c5`——空指针写入。`Saved\Crashes` 里躺了一排记录。当时项目正在 P0 收尾，改动密集，我的节奏是：崩了，重启，改，再崩。循环了一整天。

晚上才停下来认真查。所有崩溃指向同一片区域，最后锁定一个文件：`AlertHUDManager.cpp`。

疑点很朴素：**这个文件的大小，和 AlertTimelineWidget.cpp 一模一样——16822 字节。** 打开看，内容也一模一样。

**这个文件的内容，被整个覆盖成了另一个文件。**

时间线拼出来是这样的：前一晚 19:58，我"最后修改"了一次 AlertHUDManager.cpp——那次写入就是把别的文件的内容写了进去。编辑器一直开着，Live Coding 热重载试图编译这个内容完全错乱的编译单元，编译失败，引擎加载了损坏的二进制——空指针写入，崩溃。编辑器开着就反复触发，一天 9 次。

修复本身不复杂：`git show HEAD` 把原始内容捞回来，重新打上本来要做的修改，清理掉根目录攒下的 40 多个诊断脚本。崩溃停了。

## 但这其实是我一年内撞的第三次

单看 9/7，像是一次倒霉的误操作。把它和前后两起摆在一起，模式就清楚了——**三次事故，同一个根因的三个形态**：

**8/23，改了，没编进去。** 无人机颜色修复合入后，重启运行还是旧颜色。代码逻辑对、材质资产对、参数链路对，现象就是不变。查到下午才在二进制层找到突破口：DLL 的编译时间 11:59:38，**早于**所有源码修改（13:59、13:19）。新代码从来没进过二进制。中间还有一个差点带偏我的现象：用 MCP Python 直接改运行时材质参数，颜色立刻变了——几秒后又被旧逻辑覆盖回去。当时这看起来很像"资产有问题"，现在回头看，它恰恰证明跑的是旧代码。

**9/7（这次），文件内容被覆盖。** 写的和跑的不是同一个东西，编译链直接崩。

**9/8，编了，没生效。** 围栏虚线和地标光柱悬在空中，离地 64.3 米。第一反应是高程数据错了——但用运行时工具实测坐标转换函数，输出完全正确（期望 15.5m 的位置，函数给了 15.49m）。再读 Actor 实际位置：79.8m。查时间戳：源码改到 17:11，DLL 停在 13:13。**又是旧二进制。** 停 PIE、编译、重启 PIE，围栏落回 15.5m，前后 20 分钟。

## 根因

三次不是"某人某次手滑"。共同根因是：**整个工作流里，没有任何机制保证"运行的代码 = 你以为正在运行的代码"。**

文件可能被覆盖（9/7）、改了可能没编译（8/23）、编译了 PIE 可能没重载（9/8）——每个环节都靠人记、靠人查。一个人加一个 AI 帮手、高频改动的场景里，人的记忆是最靠不住的那一环。

还有一层共性值得单独说：8/23 和 9/8 两次，**现象都完美伪装成了数据问题**——旧颜色、悬空 64 米。如果我按现象去修数据，会永远修不好，还会把数据改错。

## 怎么修的

9 月 21 日起，三层防护全部在岗。每一层对应一种事故形态：

1. **写盘前校验**——`Protect-L4SourceWrite.ps1`：改 `Source/` 或 `Content/` 任何文件之前先跑，校验文件内容跟它的身份一致，退出码非 0 禁止写盘。对付 9/7 型。
2. **pre-commit 钩子**——提交前再拦一道。对付绕过脚本的写盘。
3. **WriteGuard**——编辑器侧保护。对付编辑器内的误操作。

再加一条纪律：改完不编译不验，等于没改。

## 给看的人一句警醒

**排查"行为不对"的第一动作，不是查逻辑，是核对二进制时间戳。** DLL 比源码旧，什么都别查，先编译。这一个动作，能帮我省下的不是几个小时，是几天的方向性错误。如果你的团队里有 AI 参与写码，"文件名和内容一致"这件事交给工具校验——别交给眼睛。

## 给自己的提醒

> 9/7 那天我循环了 9 次崩溃才停下来查根因——崩溃第 3 次的时候就该停下。崩溃重复发生时，暂停比重启更有用。

## 下回怎么做（checklist，可直接拿走）

- [ ] 写盘前跑校验脚本，退出码非 0 立即停手，不抱"这次应该没事"的侥幸
- [ ] "行为不对 / 位置不对"类问题，**第一动作是核对 `Binaries/Win64/*.dll` 时间戳 vs 源码修改时间**，确认跑的是新代码，再开始怀疑数据
- [ ] Live Coding 编译成功后必须重启 PIE，旧会话不会自动应用补丁
- [ ] 用实测对位排查，不用猜：调一次转换函数看输出，对比实际值，30 秒分清"算错了"还是"没生效"
- [ ] AI 协作时，"文件名与内容一致"交给工具校验，不靠眼睛
- [ ] 崩溃重复发生（≥3 次同形态），停止重启循环，先去找共性再动手
