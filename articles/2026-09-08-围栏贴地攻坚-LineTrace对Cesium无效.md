# 让电子围栏贴在地形上：物理射线为什么打不到 Cesium 地面

> 现象一句话：电子围栏圆柱和地标光柱要"长"在 Cesium 地面上，最先想到的向下打射线求地面（LineTrace）——对 Cesium 地形根本无效；贴地最后走的是"地理高程数据"这条账。

## 现象

低空数字孪生场景里，电子围栏是包络在真实地理空间上的圆柱体，地标光柱是从地面向上堆叠的细长信标。它们的位置由经纬度决定，但**底部的高度**必须落在地面上——高了悬空，低了埋进山体。

最直觉的做法：在目标点向下打一条物理射线（LineTrace），打到什么算什么，那就是地面。这套在普通 UE 场景里百试百灵的做法，在这里失灵了。

## 排查路径与选型

**第一关：LineTrace 为什么无效。** Cesium 的 World Terrain 是流式加载的 3D Tiles——它在屏幕上是一块实实在在的地形，但它不是物理引擎里的碰撞体（没有可供射线命中的 collision mesh，默认情况下）。物理射线打下去，什么都打不到，仿佛地面不存在。结论记录在项目手册里：贴地定位不可用 LineTrace。

**第二关：那贴地靠什么。** 改用地理侧的工具链：用 SRTM 高程数据（30m 分辨率 + EGM96 大地水准面校正）查目标经纬度处的地面海拔，再经 `CesiumGeoreference` 的坐标转换把"经纬度+海拔"换算成 UE 世界坐标，得到围栏底面的 Z 值（GroundZ）。这条链路不依赖地形是否真的加载出来——只要经纬度确定，地面高度就是确定值。

**第三关：高度有了，锚点不准还是会埋。** 9/5 又暴露一个 related 问题：地标光柱底部阶梯圆台整个看不见——锚点写的是海拔 10m，而杭州实际地形在 20-60m 以上，底部结构全在地形下面。当时摆了三个候选：

| 方案 | 做法 | 取舍 |
|------|------|------|
| A. 硬编码修正表 | 按 7 个地标的实际海拔逐一核对填入 | 最可靠，只有 7 个值，选一个对一个 |
| B. Cesium SampleHeight 异步 API | 运行时向 tileset 采样精确高度 | 精确但实现复杂，异步流程要接回主线程 |
| C. 整体抬高锚点 | 所有地标统一抬高 | 低处地标会浮空，否决 |

选了 A：7 个值不值得为它引入异步架构。

**第四关：9/8 的"悬浮 64.3 米"。** 围栏和光柱悬在空中——看起来像高程数据错了，但这次给了整条方法链一次完整的实战检验。用运行时工具逐步实测：

1. 读 Georeference 原点：lat 30.284 / lon 119.998 / height 0，正常；
2. 直接调坐标转换函数 `TransformLongitudeLatitudeHeightPositionToUnreal(30.27, 119.99, 15.73)`：返回 Z = 1549cm——**转换函数本身是对的**；
3. 读围栏 Actor 实际位置：Z = 7976cm（79.8m），和期望 15.5m 差 64.3m；
4. 查源码与 DLL 时间戳：源码改到 17:11，DLL 停在 13:13——**运行的不是新代码**（这是另一类事故，单独成篇）。

停 PIE、重新编译、重启 PIE 后复测：围栏 A 落回 15.5m（12.73m 地面 + 3m 偏移，期望 15.73 ✓），围栏 B 落回 14.7m（11.73 + 3 ✓），地标光柱从 9.3m 起步、12 段 × 25m 阶梯贴地堆叠至 291.7m ✓。

## 根因

一句话：**Cesium 地形是"显示资产"不是"物理资产"，物理引擎的账在这套系统里算不了地理的账。**

贴地问题本质是地理问题（这个经纬度的地面海拔是多少），不是物理问题（这束射线能不能打到东西）。用 LineTrace 是在用错误的账本记账——不是射线不够长，是两本账根本不通。

## 修复

- 围栏/地标贴地：SRTM 高程 + EGM96 + `CesiumGeoreference` 转换算 GroundZ（项目手册 §2.1 的已落地项）；
- 地标锚点：7 个实际海拔硬编码修正表（方案 A）；
- 预留：需要更高精度的场景再评估 SampleHeight 异步采样（方案 B）。

## 下回怎么做

- [ ] **Cesium 地形上禁用 LineTrace 思路**——凡是"贴地/离地高度"一律走高程数据账；物理射线只留给真正有碰撞体的自建网格
- [ ] **地理显示异常的先验排查顺序**：实测转换函数输出 → 对比 Actor 实际值 → 对不上先查二进制同步（DLL 时间戳），再查高程数据
- [ ] **锚点海拔用实测值**，不信"大概应该够"——10m 的想当然换来一个完全看不见的底座
- [ ] **少即是多**：7 个数据点用硬编码表，不为它引入异步架构；精度需求真到了再升级方案
